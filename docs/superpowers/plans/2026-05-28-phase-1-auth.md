# Phase 1 — Authentication & Multi-User Core — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A logged-in single-user experience: first-run setup wizard, credentials + OIDC login, password reset, registration-mode-gated `/register`, admin user creation, role-based access to `/admin/*`, with a Bilan-styled app shell behind a guarded `(authenticated)` route group.

**Architecture:** Better Auth runs as a Next.js route handler at `/api/auth/[...all]`, built from a cached handler factory that reads dynamic providers and settings out of the DB (no restart on config change). All business logic lives in `src/server/services/*` (pure, unit-tested); Server Actions and Route Handlers are thin wrappers. RBAC permissions are checked in a `requirePermission(...)` helper called from both server components and actions; raw page-level redirection lives in `src/proxy.ts` (the route-level middleware, renamed for Next 16). Per spec §3.5 / §5.1, the setup wizard is the only allowed path when `User.count() === 0`.

**Tech Stack:** Next.js 16 App Router · Better Auth (with `admin`, `twoFactor`, `passkey`, `openAPI` plugins) · `@node-rs/argon2` (built into Better Auth) · Prisma 7 · MariaDB 11 · shadcn `form`/`input`/`label`/`select`/`alert`/`avatar`/`dropdown-menu`/`tabs` · `react-hook-form` + `zod` · `next-intl` · `lucide-react` icons · Vitest (integration via mariadb-test) · Playwright (e2e, fr+en locales).

> **Spec references:** §3.1 layered architecture, §3.5 / §5.1 bootstrap, §4.1 identity & RBAC, §4.2 `AdminSignupToken`, §4.8 `AuthProvider` / `AppSetting` / `AuditLog` / `UserPreference`, §5.2 login flow, §5.3 registration modes, §5.9 admin settings hot reload, §6.3 argon2id, §6.4 sessions, §6.5 CSRF, §6.7 rate limiting, §6.8 audit log events, §8.4 Better Auth configuration, §8.8 hot reload of settings.

> **TDD philosophy:** schema/migration/setup steps are verified by **commands that must succeed**. Logic-bearing code (services, permission checks, registration-mode guards, rate limiter) follows strict test-first TDD. UI pages are verified by Playwright e2e + a `curl` header/redirect check; only the form-handling server actions get unit tests.

> **Out of scope for Phase 1** (deferred — flagged inline where they would naturally appear):
> - Default-category seeding at signup (Group D `Category` model lands in Phase 3.1; the wizard creates the user without categories).
> - 2FA enrolment UI and passkey enrolment UI — the plugins are loaded so the **endpoints exist**, but the user-facing flows live under `/settings/security` which is Phase 8.4. Login form handles the `redirect to /login/2fa` step if Better Auth requires it, but the enrolment page is a stub.
> - Group invitations land in Phase 2.3; only **admin-token-based** registration is wired here.
> - Email sending requires SMTP — the wizard captures SMTP config, but if SMTP is not configured the magic-link/reset flows write the link to `AuditLog.metadata` and surface it in `/admin/audit-log` (Phase 8.4). A console fallback `logger.info("magic link: <url>")` is added so dev users can copy/paste it. Real SMTP delivery is Phase 8.4.

Create `src/server/auth/rate-limit.ts`:
```ts
type Bucket = { count: number; resetAt: number };

export type Outcome = { allowed: true } | { allowed: false; retryAfterSec: number };

export class RateLimiter {
  private buckets = new Map<string, Bucket>();
  constructor(private opts: { max: number; windowMs: number }) {}

  consume(key: string): Outcome {
    const now = Date.now();
    const bucket = this.buckets.get(key);
    if (!bucket || bucket.resetAt <= now) {
      this.buckets.set(key, { count: 1, resetAt: now + this.opts.windowMs });
      return { allowed: true };
    }
    if (bucket.count < this.opts.max) {
      bucket.count += 1;
      return { allowed: true };
    }
    return { allowed: false, retryAfterSec: Math.ceil((bucket.resetAt - now) / 1000) };
  }
}

// Singletons per spec §6.7.
export const loginLimiter = new RateLimiter({ max: 5, windowMs: 15 * 60_000 });
export const registerLimiter = new RateLimiter({ max: 3, windowMs: 60 * 60_000 });
export const resetLimiter = new RateLimiter({ max: 3, windowMs: 60 * 60_000 });
```

```ts
import type { PrismaClient } from "@prisma/client";

type Entry = { value: unknown; expiresAt: number };

export class AppSettingsService {
  private cache = new Map<string, Entry>();

  constructor(
    private db: PrismaClient,
    private opts: { ttlMs: number } = { ttlMs: 60_000 },
  ) {}

  async get<T = unknown>(key: string): Promise<T | null> {
    const cached = this.cache.get(key);
    const now = Date.now();
    if (cached && cached.expiresAt > now) return cached.value as T;

    const row = await this.db.appSetting.findUnique({ where: { key } });
    if (!row) return null;
    this.cache.set(key, { value: row.value, expiresAt: now + this.opts.ttlMs });
    return row.value as T;
  }

  async set(key: string, value: unknown, updatedById: string): Promise<void> {
    await this.db.appSetting.upsert({
      where: { key },
      create: { key, value: value as never, updatedById },
      update: { value: value as never, updatedById },
    });
    this.cache.delete(key);
  }
}

import { db } from "@/server/db";
export const appSettings = new AppSettingsService(db);
```

```ts
import { betterAuth, type BetterAuthOptions } from "better-auth";
import { prismaAdapter } from "better-auth/adapters/prisma";
import { db } from "@/server/db";
import { env } from "@/env";
import { appSettings } from "@/server/services/settings/app-settings";
import { authPlugins } from "./plugins";

type Handler = ReturnType<typeof betterAuth>;
let cached: { handler: Handler; builtAt: number } | null = null;
const CACHE_TTL_MS = 60_000;

async function buildOptions(): Promise<BetterAuthOptions> {
  const credentialsEnabled = (await appSettings.get<boolean>("credentials_enabled")) ?? true;
  const minPasswordLength = (await appSettings.get<number>("min_password_length")) ?? 12;

  return {
    appName: "Bilan",
    secret: env.AUTH_SECRET,
    baseURL: env.APP_URL,
    trustedOrigins: [env.APP_URL],
    database: prismaAdapter(db, {
      provider: "mysql",
      // Rename Better Auth's "account" model to our "AuthAccount" (we keep
      // BankAccount free of the auth namespace).
      schema: { account: { modelName: "AuthAccount" } },
    }),
    emailAndPassword: {
      enabled: credentialsEnabled,
      minPasswordLength,
      autoSignIn: true,
    },
    session: {
      expiresIn: 60 * 60 * 24 * 7, // 7 days
      updateAge: 60 * 60 * 24,     // refresh after 1 day
      cookieCache: { enabled: true, maxAge: 5 * 60 },
    },
    advanced: {
      cookies: {
        sessionToken: { attributes: { sameSite: "strict", httpOnly: true } },
      },
    },
    plugins: authPlugins,
  };
}

export async function getAuth(): Promise<Handler> {
  const now = Date.now();
  if (cached && now - cached.builtAt < CACHE_TTL_MS) return cached.handler;
  const handler = betterAuth(await buildOptions());
  cached = { handler, builtAt: now };
  return handler;
}

export function invalidateAuthCache(): void {
  cached = null;
}
```

```ts
import { headers as nextHeaders } from "next/headers";

export function buildPermissionsChecker(database: PrismaClient) {
  return async function hasPermission(userId: string, permissionKey: string): Promise<boolean> {
    const user = await database.user.findUnique({
      where: { id: userId },
      include: { roles: { include: { role: { include: { permissions: { include: { permission: true } } } } } } },
    });
    if (!user) return false;
    return user.roles.some((ur) =>
      ur.role.permissions.some((rp) => rp.permission.key === permissionKey),
    );
  };
}
```

```ts
import type { PrismaClient, AuthProvider } from "@prisma/client";
import { dataKey } from "@/server/crypto/keys";
import { decrypt } from "@/server/crypto/encryption";

export class DynamicProviderCache {
  private cache: { providers: AuthProvider[]; expiresAt: number } | null = null;

  constructor(
    private db: PrismaClient,
    private opts: { ttlMs: number } = { ttlMs: 60_000 },
  ) {}

  async get(): Promise<AuthProvider[]> {
    const now = Date.now();
    if (this.cache && this.cache.expiresAt > now) return this.cache.providers;
    const providers = await this.db.authProvider.findMany({ where: { enabled: true } });
    this.cache = { providers, expiresAt: now + this.opts.ttlMs };
    return providers;
  }

  invalidate(): void {
    this.cache = null;
  }
}

import { db } from "@/server/db";
export const providerCache = new DynamicProviderCache(db);

export type ResolvedOidc = {
  providerId: string;
  clientId: string;
  clientSecret: string;
  issuer: string;
  scopes: string[];
};

/** Decrypt clientSecretEnc into a structure ready to feed Better Auth. */
export function resolveOidcProvider(row: AuthProvider): ResolvedOidc | null {
  if (row.type !== "oidc") return null;
  if (!row.issuer || !row.clientId || !row.clientSecretEnc) return null;
  return {
    providerId: row.key,
    clientId: row.clientId,
    clientSecret: decrypt(row.clientSecretEnc, dataKey),
    issuer: row.issuer,
    scopes: row.scopes ? row.scopes.split(",").map((s) => s.trim()) : ["openid", "email", "profile"],
  };
}
```

```ts
  displayName: z.string().min(1),
  enabled: z.boolean(),

    parsed.clientSecret && parsed.clientSecret.length > 0

      clientId: parsed.clientId ?? null,

      scopes: parsed.scopes ?? null,
      updatedById: actor.id,
    },
    update: {
      type: parsed.type,
      displayName: parsed.displayName,
      enabled: parsed.enabled,
      issuer: parsed.issuer ?? null,
      clientId: parsed.clientId ?? null,
      ...(clientSecretEnc ? { clientSecretEnc } : {}),
      scopes: parsed.scopes ?? null,
      updatedById: actor.id,
    },
  });

    entityId: row.id,
```

```ts
import { randomBytes } from "node:crypto";
import { db } from "@/server/db";

export async function createSignupToken(input: {
  description?: string;
  maxUses?: number | null;
  expiresAt?: Date;
  createdById: string;
}): Promise<{ id: string; token: string }> {
  const token = randomBytes(24).toString("base64url");
  const row = await db.adminSignupToken.create({
    data: {
      token,
      description: input.description ?? null,
      maxUses: input.maxUses ?? null,
      expiresAt: input.expiresAt ?? null,
      createdById: input.createdById,
    },
  });
  return { id: row.id, token };
}

export async function consumeSignupToken(token: string): Promise<{ ok: boolean }> {
  const row = await db.adminSignupToken.findUnique({ where: { token } });
  if (!row) return { ok: false };
  if (row.revokedAt) return { ok: false };
  if (row.expiresAt && row.expiresAt.getTime() < Date.now()) return { ok: false };
  if (row.maxUses !== null && row.usedCount >= row.maxUses) return { ok: false };
  await db.adminSignupToken.update({
    where: { id: row.id },
    data: { usedCount: { increment: 1 } },
  });
  return { ok: true };
}

export async function revokeSignupToken(id: string): Promise<void> {
  await db.adminSignupToken.update({ where: { id }, data: { revokedAt: new Date() } });
}

export async function listSignupTokens() {
  return db.adminSignupToken.findMany({ orderBy: { createdAt: "desc" } });
}
```

```ts
// After the setup-needed branch, before returning intlMiddleware:
const authedPath = /^\/(fr|en)\/(dashboard|transactions|accounts|budgets|categories|groups|import|settings|admin)(\/|$)/;
if (authedPath.test(pathname)) {
  // Cheap presence check on the session cookie; the layout's requireSession()
  // performs the real validation. The proxy is fast-path only.
  const cookie = req.cookies.get("better-auth.session_token") ?? req.cookies.get("__Secure-better-auth.session_token");

    const url = req.nextUrl.clone();
    url.pathname = "/fr/login";
    return Response.redirect(url, 307);
  }
}
```

> **Why a cookie sniff in the proxy?** Spec §3.2 says guards live in layouts (they have DB access). The proxy is purely UX: a missing cookie means an unauthenticated bot/user hits a 307 to `/login` before the page is rendered — no DB round-trip. The layout's `requireSession()` still runs and is the authoritative check.
